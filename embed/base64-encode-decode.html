The Base64 alphabet

Base64 uses 64 printable characters. Three bytes (24 bits) become four characters of 6 bits each. If the input is not a multiple of three bytes, = padding fills the last group.

IndexStandard (RFC 4648 §4)URL-safe (§5)

26 to 51a to za to z
52 to 610 to 90 to 9
62+− (hyphen)
63/_ (underscore)
Padding== or omitted

Formulas

How the numbers are worked out.

memory

Three bytes to four characters

Bytes are read as a stream of bits and cut into 6-bit groups, each mapped to one alphabet character.

24 bits = 3 bytes = 4 characters
straighten

Output length

Every 3 input bytes give 4 characters, rounded up, with padding to fill.

length = 4 × ceil(bytes ÷ 3)
overhead ≈ 33%
tag

Padding

One leftover byte adds ==, two leftover bytes add =.

bytes mod 3 = 1 → "==", = 2 → "=", = 0 → none

How to encode and decode Base64

  • Choose Encode or Decode.
  • Paste your text, or hex bytes.
  • Set the URL-safe, padding and line wrapping options.
  • Copy the output, or use it as the next input to check a round trip.

Base64 is an encoding, not encryption. Anyone can decode it, so never use it to hide secrets.

Frequently asked questions

What is Base64 used for?expand_more

Carrying binary data through text-only systems, such as email attachments, data URIs, JSON tokens (JWT) and HTTP Basic authentication headers.

Is Base64 encryption?expand_more

No. It only re-writes bytes with a different alphabet. Anyone can decode it.

Why does the output end with =?expand_more

Padding. Base64 works in groups of 3 bytes. When the input is not a multiple of 3, one or two = characters complete the last group.

What is URL-safe Base64?expand_more

A variant that uses - and _ instead of + and /, so it can sit in URLs and file names. JWTs also leave off the = padding.

Why is the output bigger?expand_more

Every 3 bytes become 4 characters, about 33% larger, plus line breaks if you wrap lines.
