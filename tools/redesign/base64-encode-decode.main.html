The Base64 alphabet

Base64 uses 64 printable characters. Three bytes (24 bits) become four characters of 6 bits each. If the input is not a multiple of three bytes, = padding fills the last group.

IndexStandard (RFC 4648 §4)URL-safe (§5)
0 to 25A to ZA to Z
26 to 51a to za to z
52 to 610 to 90 to 9
62+− (hyphen)
63/_ (underscore)
Padding== or omitted

Formulas

How the numbers are worked out.

memory

Three bytes to four characters

Bytes are read as a stream of bits and cut into 6-bit groups, each mapped to one alphabet character.

24 bits = 3 bytes = 4 characters
straighten

Output length

Every 3 input bytes give 4 characters, rounded up, with padding to fill.

length = 4 × ceil(bytes ÷ 3)
overhead ≈ 33%
tag

Padding

One leftover byte adds ==, two leftover bytes add =.

bytes mod 3 = 1 → "==", = 2 → "=", = 0 → none

Where Base64 is used

  • Data URIs: small images or fonts embedded in HTML or CSS as data:image/png;base64,....
  • Email (MIME): attachments are Base64 with lines wrapped at 76 characters (RFC 2045).
  • HTTP Basic authentication: user:pass becomes dXNlcjpwYXNz in the Authorization header. It is encoding, not protection.
  • JWTs: the header and payload use URL-safe Base64 without padding, for example {"alg":"HS256","typ":"JWT"} becomes eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.
  • JSON and XML: a way to carry binary data inside text formats.

Why a decode fails

  • The text contains characters outside the alphabet, such as spaces or a stray quote.
  • The length is wrong: a valid unpadded length can never leave exactly 1 character in the last group.
  • The input is URL-safe (- and _) but decoded as standard, or the other way round.
  • Padding was removed. Add = until the length is a multiple of 4, or tick the URL-safe option.
  • The bytes are not valid UTF-8 text, for example an image. Decode them as hex bytes instead.

Frequently asked questions

What is Base64 used for?expand_more

Carrying binary data through text-only systems, such as email attachments, data URIs, JSON tokens (JWT) and HTTP Basic authentication headers.

Is Base64 encryption?expand_more

No. It only re-writes bytes with a different alphabet. Anyone can decode it.

Why does the output end with =?expand_more

Padding. Base64 works in groups of 3 bytes. When the input is not a multiple of 3, one or two = characters complete the last group.

What is URL-safe Base64?expand_more

A variant that uses - and _ instead of + and /, so it can sit in URLs and file names. JWTs also leave off the = padding.

Why is the output bigger?expand_more

Every 3 bytes become 4 characters, about 33% larger, plus line breaks if you wrap lines.

Is Base64 larger than hex?expand_more

No, it is smaller. Base64 grows data by about 33% (3 bytes become 4 characters) while hex doubles it (1 byte becomes 2 characters). A 1 KB input is 1,368 Base64 characters or 2,048 hex characters.

Why does my Base64 decode fail?expand_more

Usual causes are characters outside the alphabet, a wrong length, missing padding, mixing URL-safe and standard alphabets, or bytes that are not valid UTF-8 text such as an image.

Does it handle UTF-8, accents and emoji?expand_more

Yes. Text is converted to UTF-8 bytes first, so cafe with an accent encodes to Y2Fmw6k= and the grinning-face emoji to 8J+YgA==.

How does Base64 work in HTTP Basic authentication?expand_more

The username and password joined by a colon are Base64-encoded, so user:pass becomes dXNlcjpwYXNz. Anyone can decode it, so use HTTPS and never treat it as security.

How much bigger does an image become as a data URI?expand_more

About 33% bigger as Base64. A 10 KB image (10,240 bytes) becomes 13,656 characters, plus the data URI prefix.
