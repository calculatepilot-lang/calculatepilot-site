    How base conversion works

    • Integer part, any base → decimal: multiply each digit by its place value (baseᵏ) and sum.
    • Decimal → any base: repeatedly divide by the target base; the remainders, read from last to first, are the digits.
    • Fractional part → any base: repeatedly multiply the fraction by the target base; the integer part produced each time is the next digit.

    Frequently asked questions

    Why do some fractions never terminate in another base?expand_more

    A fraction terminates in base b exactly when its reduced denominator's only prime factors are also prime factors of b. 0.1 (1/10) terminates in decimal but repeats forever in binary, because 5 is not a factor of 2 — the same reason 1/3 repeats in decimal.

    What digits does a base above 10 use?expand_more

    After 9, letters continue the sequence: A=10, B=11, … up to Z=35, allowing bases up to 36. Hexadecimal (base 16) uses 0–9 and A–F.

    Why is base 16 so common in computing?expand_more

    Each hex digit represents exactly 4 binary bits, so a byte is always exactly 2 hex digits — a much more compact and readable way to write binary data, used for memory addresses, color codes and more.

    How large a number can this handle?expand_more

    The integer part supports arbitrarily many digits (exact BigInt arithmetic); the fractional part is computed to 20 digits in the target base, noting if the expansion is truncated rather than exact.

    What's the difference between octal and hexadecimal?expand_more

    Both are shorthand for binary: octal (base 8) groups bits in 3s, hexadecimal (base 16) groups them in 4s. Hex is more common today because it aligns with 8-bit bytes; octal remains in use for Unix file permissions.
