    Two's complement, briefly

    Two's complement represents negative numbers so that addition and subtraction work identically for signed and unsigned values in hardware. To negate a value: flip every bit, then add 1. The top bit acts as the sign: 0 for non-negative, 1 for negative.

    Shift types

    • LSL / LSR (logical shift left/right): bits shifted in are always 0.
    • ASR (arithmetic shift right): preserves the sign bit — used for signed division by powers of two.
    • ROL / ROR (rotate): bits that fall off one end wrap around to the other.

    Subtracting by adding the two's complement

    Hardware turns A − B into A + (−B). For 7 − 5 at 8 bits: −5 is 11111011, and 00000111 + 11111011 = 1 00000010. Drop the carry out of bit 8 and you get 00000010, which is 2.

    Frequently asked questions

    Why does register width matter?expand_more

    It sets how many bits are available to store the result. An 8-bit register can hold unsigned values 0–255; anything larger overflows and the extra high bits are discarded, just as in real hardware.

    How do I read a negative number in two's complement?expand_more

    If the leading bit is 1, the value is negative: flip every bit, add 1, and that gives the binary magnitude — then negate. E.g. in 8 bits, 11111011 flips to 00000100, +1 = 00000101 = 5, so 11111011 represents −5.

    What's the difference between LSR and ASR?expand_more

    LSR (logical shift right) always fills the vacated high bit with 0, treating the value as unsigned. ASR (arithmetic shift right) fills it by copying the sign bit, so a negative two's-complement number stays negative — equivalent to floor division by a power of two.

    Why does 1111 + 0001 overflow in a 4-bit register?expand_more

    1111 (15) + 1 = 16 = 10000 in binary, which needs 5 bits. A 4-bit register can't hold it, so the leading 1 is dropped, leaving 0000 and an overflow/carry flag — the same "wraps to zero" behavior real 4-bit hardware shows.

    Can I enter more bits than the register width?expand_more

    You can, but the value is masked (truncated) to the chosen width before the operation runs, matching what happens when a value doesn't fit in a real register.

    How do I add binary numbers?expand_more

    Add column by column from the right: 0+0=0, 0+1=1, 1+1=10 (write 0, carry 1) and 1+1+1=11 (write 1, carry 1). For example 1011 + 0110 = 10001, which is 11 + 6 = 17.

    How do I convert binary to decimal and back?expand_more

    Add the place values of the 1 bits: 101101 = 32 + 8 + 4 + 1 = 45. To convert decimal to binary, divide by 2 repeatedly and read the remainders from the bottom up: 45 becomes 101101.

    What range does each register width hold?expand_more

    8-bit holds 0 to 255 unsigned or -128 to 127 signed, 16-bit holds 0 to 65,535 or -32,768 to 32,767, 32-bit holds 0 to 4,294,967,295 or -2,147,483,648 to 2,147,483,647, and 64-bit holds 0 to 18,446,744,073,709,551,615.

    Why does 3 - 5 show an overflow?expand_more

    The result is negative, and an unsigned register cannot hold a negative number. At 8 bits it wraps to 11111110, which is 254 unsigned or -2 read as two's complement.

    How does binary division handle remainders?expand_more

    The calculator returns the whole-number quotient, truncated toward zero, and shows the remainder separately. For example 1101 divided by 0100 is 13 divided by 4, so the quotient is 0011 (3) with remainder 1.
