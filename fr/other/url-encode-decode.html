Quels caractères sont encodés en pourcentage

L'encodage en pourcentage écrit un caractère sous la forme % suivi de la valeur hexadécimale de chacun de ses octets UTF-8. encodeURI() conserve les caractères qui structurent une URL. encodeURIComponent() les encode, ce qui est ce qu'il vous faut pour une valeur de requête unique.

Comment les chiffres sont calculés.

Encodage en pourcentage

Chaque octet de la forme UTF-8 du caractère devient un signe pourcentage suivi de deux chiffres hexadécimaux.

%C2%B3 = ³ (deux octets UTF-8)
espace = %20
data_object

Composant ou URL complète

Encodez une valeur isolée avec l’option composant. Encodez une adresse complète avec l’option URL complète afin que : / ? & = # restent inchangés.

encodeURIComponent(valeur)
encodeURI(url)
lock_open

Décodage

Chaque séquence %XX est reconvertie en son octet, et les octets sont lus en UTF-8.

decodeURIComponent(texte)

Comment encoder ou décoder une URL

  • Choisissez Encoder un composant, Encoder une URL complète ou Décoder.
  • Collez votre texte. Utilisez les exemples pour voir des cas typiques.
  • Copiez le résultat, ou utilisez-le comme entrée suivante pour faire un aller-retour.
  • Consultez le tableau pour chaque paramètre de requête.

L'encodage transforme le texte en une forme sûre pour les URL. Ce n'est pas du chiffrement et il ne cache rien. Ne mettez jamais de secrets dans une URL.

Questions fréquentes

Quelle est la différence entre encodeURI et encodeURIComponent ?expand_more

encodeURI conserve des caractères tels que : / ? & = # afin qu’une adresse complète continue de fonctionner. encodeURIComponent les encode, utilisez-le donc pour une valeur isolée à l’intérieur d’une URL.

Quand un espace doit-il être %20 et quand + ?expand_more

%20 est correct partout dans une URL. Un + ne signifie un espace que dans les données de formulaire HTML (application/x-www-form-urlencoded), comme les chaînes de requête issues de formulaires.

Pourquoi ³ devient-il %C2%B3 ?expand_more

Les caractères non ASCII sont d'abord transformés en octets UTF-8, et chaque octet est écrit en hexadécimal. ³ correspond aux deux octets C2 et B3.

Pourquoi le décodage échoue-t-il avec une erreur de format incorrect ?expand_more

Un % doit être suivi de deux chiffres hexadécimaux, et les octets doivent former de l'UTF-8 valide. Un % isolé ou une séquence tronquée provoque cette erreur.

Ces données sont-elles envoyées quelque part ?expand_more

Non. Tout s'exécute dans votre navigateur.
